📖 감사로그(audit) action 가이드

← 감사 로그 목록
감사로그(log_audit)는 시스템에서 일어나는 의미 있는 변경·조회 이벤트를 구조화된 형태로 영구 기록합니다. action(행위 코드) + target_entity(대상 테이블) + actor(누가) + result(결과) + before/after JSON(변경 내역) 이 핵심 컬럼이며, 모든 이벤트는 동시에 5경로(① log_audit DB ② Logback JSON ③ Spring Event ④ MariaDB server_audit ⑤ binlog/CDC)로 팬아웃됩니다.

result 값: SUCCESS 정상 처리 · FAIL 4xx 검증/권한 실패 · ERROR 5xx 또는 예외 · LOCKED 로그인 잠금 · DENIED 정책 거부

섹션

🔐 인증·세션·2FA

로그인 시도, 거부, 2FA TOTP 활성화·검증 이벤트. tb_member·tb_admin·tb_employee·auth 네 가지 entity 가 user_type 에 따라 분기 적재됩니다. 로그인 성공/실패 자체는 log_login 에도 별도 기록되며, 감사 측에는 거부 사유·메타데이터를 남깁니다.

action entity 발생 시점 주요 result
LOGIN tb_member · tb_admin · tb_employee · auth 로그인 시도 (성공 또는 실패) — 정상 인증 시 SuccessHandler, 실패 시 FailureHandler 가 발행 SUCCESS FAIL LOCKED
LOGIN_DENY tb_admin 관리자 인증은 통과했지만 ① IP 화이트리스트 위반 ② ROLE_STAFF 미만 가드에서 거부 — 즉시 세션 무효화 DENIED
LOGIN_2FA tb_admin 관리자 2FA TOTP 검증 단계 — /admin/login/2fa 진입 후 코드 검증 결과 SUCCESS FAIL
2FA_ENABLE tb_admin 관리자 본인이 2FA TOTP 를 신규 활성화 (QR 등록 후 첫 검증 통과) SUCCESS

👤 회원·직원·관리자 — 탈퇴/퇴사

계정 라이프사이클의 종료 이벤트. after_value JSON 에 사유 카테고리와 자유 텍스트 note 가 보관되며, PII 최소화 정책상 자유 텍스트는 DB 컬럼이 아닌 감사 로그에만 남깁니다. 일반 회원/관리자/직원 CUD 는 HTTP Interceptor 가 CREATE/UPDATE/DELETE 로 자동 포착(섹션 14 참고).

action entity 발생 시점 주요 result
MEMBER_WITHDRAW tb_member_withdraw 회원 본인이 마이페이지에서 탈퇴 처리 — 보존기간 만료일이 함께 기록 SUCCESS
MEMBER_FORCE_DELETE tb_member_withdraw 관리자가 회원 관리 화면에서 강제 탈퇴 처리 SUCCESS
EMPLOYEE_WITHDRAW tb_employee_withdraw 직원 퇴사 처리 — 인사 사유 카테고리 포함 SUCCESS
ADMIN_WITHDRAW tb_admin_withdraw 관리자 계정 탈퇴 (정책상 본인 또는 상위 관리자가 처리) SUCCESS

📊 엑셀 다운로드

🌐 HTTP 자동 포착 (AuditHttpInterceptor)

/admin/** 의 POST/PUT/PATCH/DELETE 요청을 도메인 Service 가 명시적으로 audit 를 발행하지 않은 경우에도 보강 기록합니다. 도메인별 명시 audit 가 있는 경우에는 의미 있는 도메인 코드(예: BBS_ARTICLE_UPDATE) + 자동 보강(UPDATE)이 중복으로 적재될 수 있으므로 분석 시 entity 와 함께 봅니다.

actionentity발생 시점주요 result
CREATE URL의 4번째 segment /admin/system/{entity} 의 POST — 휴리스틱: 5 세그먼트 미만이면 신규 등록으로 추정 SUCCESS FAIL ERROR
UPDATE URL의 4번째 segment /admin/system/{entity}/{id} 의 POST/PUT/PATCH — 5 세그먼트 이상이면 수정으로 추정 SUCCESS FAIL ERROR
DELETE URL의 4번째 segment DELETE 메서드의 모든 /admin/** 요청 SUCCESS FAIL

요청 정보가 필요하면 `@ControllerAdvice` 로 모델에 주입한다.

### 호환성 인증 요건

이 프로젝트는 **전자정부 표준프레임워크 호환성 확인**을 받는다.
근거는 「전자정부 표준프레임워크 호환성 가이드」(2026-06-22, (사)오픈플랫폼 개발자커뮤니티) 규칙 1~7이다.
**아래는 준수 여부가 자동 점검되는 항목이므로 임의로 바꾸지 않는다.**

| 규칙 | 요건 | 이 프로젝트의 대응 |
|---|---|---|
| 1 라이브러리 변경 제한 | `org.egovframe.rte.*` jar 를 변경하지 않는다(MD5/SHA1 원본 동일) | 재패키징·클래스 치환 금지. 확장은 상속으로만 |
| 2 필수 라이브러리·버전 | `egovframe-rte-ptl-mvc`·`-fdl-cmmn`·`-psl-dataaccess`·`-fdl-logging` **4종 전부 동일 버전** 적용 + transitive Spring 버전 불변 | groupId `org.egovframe.rte`, 버전 **5.0.0** 고정. 아래 "Spring 버전 상한" |
| 3 실행환경 설정 | 트랜잭션(AOP 또는 애노테이션) + 커넥션 풀 설정 포함 | `@Transactional` + HikariCP(가이드의 "DBCP 등" 허용 범위). Java Config 방식 허용됨 |
| 4 MVC | Controller 가 DAO·NoSQL·MQ·Cache 를 직접 호출 금지, 비즈니스 로직은 주입된 Service 경유 | §7-3 Controller 규약과 R2 로 이미 강제 |
| 5 Service | `EgovAbstractServiceImpl` 확장 + 개별 인터페이스 구현. **예외 없음** | §7-1, R3 |
| 6 데이터 액세스 | MyBatis Mapper Interface 사용 시 **`MapperConfigurer` + `@EgovMapper`** | §6-4, §7-2. `@Mapper` 는 v4.3 이하 표기라 **사용 금지** |
| 7 실행환경 확장 | rte 클래스를 상속한 클래스는 `org.egovframe.rte` 패키지에 둘 수 없고 이름이 **`Egov` 로 시작할 수 없다** | §13 명명 규약, §16-8 |
| 8 전체 적용 | Controller·Service·Mapper 각 1개 이상 + 전 모듈 동일 버전·동일 아키텍처·동일 명명규칙 | primary·secondary·logging **세 계층 모두** 같은 규약 적용 |

**실행환경 5.0.0 기준선**: Spring Boot 3.5.6 / Spring Framework 6.2.11 / Spring Security 6.5.5 / MyBatis 3.5.19 / JDK 17+.

**Spring 버전 상한**: 규칙 2는 transitive Spring 버전 변경을 금지하되 **패치 버전 상향만 예외로 허용**한다.
현 지정 Spring Boot **3.5.9** 는 기준선 3.5.6 대비 패치 상향이라 **적법**하다.
**3.6.x / 4.x 로의 minor 상향은 즉시 위반**이므로 `pom.xml` 에 상한을 주석으로 남긴다.
Java 21 은 "JDK 17 이상" 요건을 충족한다.

**Flyway 는 호환성 규칙과 충돌하지 않는다**(2026-07-31 확인).
가이드에 마이그레이션 도구 지정 조항이 없고, Flyway 는 rte 바이너리도 Spring 버전도 건드리지 않는다.
단 **Flyway 를 `@Service`/`@Repository` 로 감싸지 않는다** — 규칙 4·5 의 "실질적으로 데이터를 처리하는 클래스" 로
오탐될 수 있다. §6-5 처럼 `@Configuration` 안의 `Flyway` 빈 정의로만 유지한다.

### 4-4. 계층 규약 (ArchUnit 강제 — §15)

| 규칙 | 내용 | 실측 예외 |
|---|---|---|
| R1 | 도메인 컨트롤러는 `ApiController`/`UsrController`/`MngController` 접미사만 | `config` 패키지의 기술 컨트롤러(`CspReportController` 등) |
| R2 | Controller → Mapper 직접 참조 금지 (Service 경유) | 로그인 Success/Failure 핸들러(잠금 카운터 직행) |
| R3 | `*ServiceImpl` 은 `EgovAbstractServiceImpl` 상속 (직접·간접 모두 가능) | **호환성 규칙 5 는 "예외 없음"** — 예외를 늘리지 말고 §7-1 의 공통 추상 서비스를 경유시킨다 |
| R4 | `@EgovMapper` 는 인터페이스이며 `..mapper..` 패키지에만. **`@Mapper` 사용 0건** | — |
| R5 | DB 패키지 격리 — primary↔secondary 상호 의존 금지 | primary → logging 은 허용(감사 다중 경로) |
| R6 | `common` 독립성 — primary(dto 제외)/secondary/scheduler 의존 금지 | `common/audit` → logging, `common/mail` → 메일 도메인 |

**예외를 추가할 때는 주석에 이유를 남긴다.** 이유 없는 예외가 쌓이면 규칙이 무력화된다.

## 6. 데이터베이스

### 6-1. 3-DB 분리

| DB | 접두 | 내용 | TxManager 상수 |
|---|---|---|---|
| primary | `tb_*` | 핵심 CMS | `PrimaryDataSourceConfig.TRANSACTION_MGR` (`"primaryTransactionManager"`) |
| secondary | — | 개별 프로그램·외부 API | `SecondaryDataSourceConfig.TRANSACTION_MGR` |
| logging | `log_*`, `stat_*`, `shedlock` | 로그·통계·배치 락 | `LoggingDataSourceConfig.TRANSACTION_MGR` |

각 DB는 **자체 DataSource · TransactionManager · SqlSessionFactory** 를 가진다.
`@Transactional` 에는 **반드시 `transactionManager` 를 명시**한다 — 생략하면 primary 로 잘못 붙는다.

### 6-2. 테이블 공통 규약

- **PK**: UUID v7 **`varchar(40)`** — 시간순 정렬 가능한 UUID. (001 문서의 `varchar(36)` 표기는 오기, 실측은 40)
- **감사컬럼 6종** — 전 테이블 필수.
- **soft-delete**: `delete_yn char(1)` (`Y`/`N`, 기본 `N`). 물리 삭제는 퍼지 배치에서만.
- **사용여부**: `use_yn char(1)` (`Y`/`N`, 기본 `Y`).
- **문자셋**: `utf8mb4` / `utf8mb4_uca1400_ai_ci` (MariaDB).
- 모든 컬럼에 **COMMENT** 를 단다.
- 신규 테이블은 **MariaDB DDL** 로 작성한다(매퍼와 동일하게 단일 벤더 — §6-4).

### 6-3. 테이블 템플릿 (MariaDB 실측 기준)

```sql
CREATE TABLE `tb_example` (
  `example_id`  varchar(40)  NOT NULL COMMENT '예제 ID (UUID v7)',
  `site_id`     varchar(40)  DEFAULT NULL COMMENT '사이트 ID (멀티사이트 범위)',
  `title`       varchar(200) NOT NULL COMMENT '제목',

  `delete_yn`   char(1)      NOT NULL DEFAULT 'N' COMMENT '삭제 여부 (소프트 삭제)' CHECK (`delete_yn` in ('Y','N')),
  created_by varchar(40) DEFAULT NULL COMMENT '생성자 ID',
  created_ip varchar(50) DEFAULT NULL COMMENT '생성자 IP',
  created_at timestamp   DEFAULT current_timestamp() COMMENT '생성 일시',
  updated_by varchar(40) DEFAULT NULL COMMENT '수정자 ID',
  updated_ip varchar(50) DEFAULT NULL COMMENT '수정자 IP',
```

### 6-4. 매퍼

- **`@EgovMapper` 인터페이스** + XML **`*_maria.xml` 단일**. 대상 DB 는 **MariaDB 전용**이다.
  - **MyBatis 의 `@Mapper`·`@MapperScan` 을 쓰지 않는다.** 호환성 규칙 5 는 Mapper Interface 적용 시
    표준프레임워크가 제공하는 **`MapperConfigurer` + `@EgovMapper`** 를 요구하며, `@Mapper` 는
    **실행환경 v4.3 이하** 표기다. 001 코드를 이식할 때 가장 흔히 놓치는 지점이다.
  - 스캔은 **DataSource 3개별로 `MapperConfigurer` 빈**을 둔다
    (`basePackage` = `com.gonet.{primary,secondary,logging}`, `sqlSessionFactoryBeanName` = 해당 DB 팩토리).
  - 애노테이션 FQN 은 **실제 5.0 jar 로 확인**한다(`org.egovframe.rte.psl.dataaccess.mapper.EgovMapper` 추정).
    문서와 실측이 다르면 실측이 맞다(§16-7).
  - 001 은 `_maria`/`_mysql`/`_postgres` 3종을 84개씩 유지했으나, `*MyBatisConfig` 가
    `classpath*:mapper/**/*_maria.xml` 을 **하드코딩**해 나머지 두 벤더는 한 번도 로드된 적이 없다.
    검증되지 않은 168개 파일을 동기화하는 부담만 남으므로 003 은 **maria 단일로 확정**한다(2026-07-31).
  - `_maria` 접미사는 **유지한다**. 향후 벤더가 늘어날 때 파일명 규칙을 바꾸지 않기 위해서다.
- namespace ↔ 인터페이스 FQN **1:1**.
- **전량 `#{}` 바인딩. `${}` 절대 금지** (SQL 인젝션).
  동적 정렬·컬럼명이 필요하면 **화이트리스트 매핑** 후 사용한다.
- LIKE 검색은 와일드카드(`%`, `_`)를 **이스케이프**한 뒤 바인딩한다.

### 6-5. Flyway

**스키마 변경은 Flyway 마이그레이션으로 관리한다.** 코드에서 임의 DDL 실행 금지.

#### 위치 · 네이밍

```
src/main/resources/db/migration/
├── primary/mariadb/
├── secondary/mariadb/
└── logging/mariadb/
```

**적용 범위는 3개 DB 전부**다(D2 결정, 2026-07-31). 벤더는 매퍼와 동일하게 **MariaDB 단일**(§6-4)이나,
경로에 벤더 층은 남겨 둔다 — 나중에 늘어나도 디렉터리 구조를 바꾸지 않기 위해서다.

| 형식 | 용도 | 예 |
|---|---|---|
| `V{yyyyMMdd}{NN}__{설명}.sql` | 버전 마이그레이션(1회) | `V2026080101__add_site_theme.sql` |
| `R__{설명}.sql` | 반복 실행(뷰·프로시저 등) | `R__view_user_login.sql` |

#### 구성

**Spring Boot 자동설정을 쓸 수 없다** — 이 프로젝트는 `spring.datasource` 가 아니라 커스텀 DataSource 3개를 쓴다.
따라서 **DataSource별 Flyway 빈을 명시 구성**한다.

```java
@Bean(initMethod = "migrate")
public Flyway primaryFlyway(@Qualifier(PrimaryDataSourceConfig.DATA_SOURCE) DataSource ds) {
    return Flyway.configure()
        .dataSource(ds)
        .locations("classpath:db/migration/primary/mariadb")
        .baselineOnMigrate(true)          // 기존 스키마 도입 — 현재 상태를 베이스라인으로
        .baselineVersion("0")
        .validateOnMigrate(true)
        .outOfOrder(false)
        .load();
}
```

- 마이그레이션 실행이 **DataSource 빈 생성 이후, MyBatis 사용 이전**에 끝나도록 순서를 보장한다.
- 프로파일별 활성화는 `gopcms.flyway.enabled` 로 제어한다.

#### 원칙

- **시드 데이터는 마이그레이션에 넣지 않는다.** 데모 사이트·샘플 콘텐츠는 `sql/` 에 두고 별도 집행한다.
  스키마와 데이터는 수명주기가 다르다 — 운영 재배포 때 데모 데이터가 딸려 들어가면 안 된다.
  단, **참조 데이터**(공통코드, `tb_role_url_access` 기본 규칙 등 없으면 앱이 동작하지 않는 것)는 마이그레이션에 포함한다.
- 적용된 마이그레이션 파일은 **절대 수정하지 않는다**(체크섬 불일치로 기동 실패). 수정이 필요하면 새 버전을 추가한다.
- **실행 계정**: Flyway 는 DDL 권한이 필요하다. 앱 런타임 계정에 DDL 을 주지 않는 기존 보수 방침과 충돌하므로,
  **계정 분리 여부는 [PLAN.md](PLAN.md) §6 결정 대기(D1)** 이다. 결정 전까지 로컬에서만 활성화한다.

### 7-1. Service

```java

    private final AuditLogger   auditLogger;

    @Override
    public List<Holiday> search(HolidaySearch search) {                          // 조회 — 클래스 기본(readOnly) 상속
        return mapper.findList(search == null ? new HolidaySearch() : search);
    }

    @Override
    @Transactional(transactionManager = PrimaryDataSourceConfig.TRANSACTION_MGR) // 쓰기 — 반드시 override
    public String create(HolidaySaveForm form) {
        String id = UuidV7Generator.generate();
        …
        auditLogger.record(AuditEvent.of("HOLIDAY", "CREATE", id));

    }

```

- **인터페이스 + Impl** 쌍. Impl 은 `EgovAbstractServiceImpl` 상속.
- 클래스 레벨 `readOnly = true` 가 기본, **쓰기 메서드마다 writable override**.
- 생성자 주입(필드 주입 금지). Lombok `@RequiredArgsConstructor` 사용 가능.

**호환성 규칙 5 는 예외가 없다.** `EgovAbstractServiceImpl` 을 직접 상속하기 곤란한 서비스
(모니터링·캐시 등 기술 서비스)는 규칙에서 벗어나지 말고, 가이드의 권장안대로
**`EgovAbstractServiceImpl` 을 상속한 공통 추상 서비스**를 하나 두고 그것을 상속시킨다.
상속은 **직접·간접 모두 인정**되므로 이 방식이면 규칙을 지키면서 공통 동작도 넣을 수 있다.
R3 예외 목록은 늘리지 않는다 — 부득이하면 사유를 주석에 남긴다.

## 8. 트랜잭션

### 함정 (실제 장애 이력)

| 함정 | 증상 | 대응 |
|---|---|---|
| 클래스 `readOnly=true` 가 메서드에 상속 | "Connection is read-only" 또는 **조용한 롤백** | 쓰기 메서드에 writable override |
| **자기호출** `this.txMethod()` | 프록시 우회로 `@Transactional`·`@Async` **무시** | 별도 빈 분리 또는 `@Lazy self` 주입 |
| 긴 외부호출을 트랜잭션 안에서 | 커넥션 고갈 | `NOT_SUPPORTED` / `REQUIRES_NEW` 로 격리 |
| `transactionManager` 미지정 | 엉뚱한 DB 트랜잭션에 붙음 | 항상 명시 |
| 애노테이션 변경 후 hot-swap | 반영 안 됨 | 완전 정지 → Rebuild → Run (**DevTools 금지**) |

### 자기호출 회피 패턴

```java
@Service
public class FileUploadServiceImpl … {
    private final FileUploadService self;                     // @Lazy 자기 프록시

    public FileUploadServiceImpl(@Lazy FileUploadService self, …) { this.self = self; }

    public void create(…) {
        self.scanAsync(…);        // this.scanAsync() 였다면 @Async·@Transactional 무시됨
    }
}
```

로그 기록기처럼 **항상 REQUIRES_NEW 로 떨어져야 하는 것**은 별도 Executor 빈으로 분리한다
(`WithdrawPurgeExecutor`, `RetentionPurgeExecutor` 패턴).

| `text-body-{xs,sm,md,lg}` | 본문 |
| `text-label-{xs,sm,md,lg}` | 라벨·버튼·캡션 |

**굵기는 400 / 500 / 700 만** 사용한다(`font-semibold`(600) 금지).

#### 모양

- radius: `--radius-{xsmall,small,medium,large,xlarge,max}` — **최대 12px**.
- 그림자: `--shadow-{e1,e2,e3,e4}`.
- 간격: 표준 Tailwind(16px 루트) — `p-4`=16px, `text-sm`=14px.

#### 테마 · 접근성

- `<html>` 의 `theme-*` 클래스가 `--brand-*` 램프를 스왑한다. 사이트별 지정은 `tb_site.theme` 컬럼.
- 고대비(`hc`) 모드 — `<html>.hc` + `localStorage` 유지. FOUC 방지를 위해 `<head>` 의 nonce 인라인 부트스트랩에서 복원.
- **예외**: 메일 템플릿은 이메일 클라이언트가 CSS 변수를 지원하지 않아 raw hex 허용.

### 9-2. JavaScript / CSP

**CSP**: `script-src 'self' 'nonce-…' 'strict-dynamic'` — **`'unsafe-inline'` 없음**.

이 정책의 결과로 반드시 알아야 할 것:

1. **인라인 `on*=` 핸들러는 브라우저가 실행하지 않는다.** 오류가 눈에 띄지 않고 **조용히 무시**된다.
   001에서 `onsubmit="return confirm('삭제하시겠습니까?')"` 38건이 이렇게 무력화돼,
   **확인창 없이 폼이 그대로 제출되어 삭제가 실행**됐다. 절대 쓰지 않는다.
2. **`strict-dynamic` 하에서는 host 화이트리스트가 무시된다.** CDN `<script src>` 는 nonce 없이는 차단된다
   → 외부 라이브러리는 **self-host** 하거나, nonce 를 단 스크립트가 동적 주입해야 한다(그때는 신뢰가 전파된다).
3. **htmx 의 이벤트 필터**(`hx-trigger="keyup[key=='Enter']"`)는 내부에서 `Function()`(eval)을 만들어 **CSP에 걸린다**
   → 트리거는 `click` 만 선언하고 키보드 접근성은 위임 핸들러로 처리한다.
4. nonce 를 품은 HTML 이 캐시되면 nonce 재사용으로 CSP 가 무력화된다 → **HTML 응답은 `no-store`**.

#### 대체 규약 — `data-*` + 이벤트 위임

`app.js` 가 document 에 **1회 등록**하는 위임 핸들러 계약:

| 마크업 | 동작 |
|---|---|
| `form[data-confirm="메시지"]` | 제출 전 확인창. **제출 버튼에 붙여도 인식**(버튼 우선). `\n` 은 개행으로 해석 |
| `[data-action="submit-on-change"]` | 값 변경 시 소속 폼 제출(`requestSubmit()` 우선 — `data-confirm` 검사 유지) |
| `[data-history-back]` (+ `-fallback`) | 뒤로가기, 이력 없으면 fallback URL |
| `[data-action="print"]` | 인쇄 |
| `[data-action="dialog-open"]` + `[data-dialog-target]` / `[data-action="dialog-close"]` | 네이티브 `<dialog>` 제어 |
| `[data-hide-on-error]` / `[data-src-fallback]` / `[data-show-next-on-error]` | 이미지 로드 실패 폴백 (`onerror` 대체) |
| `[data-action="toggle-contrast"]` | 고대비 토글 |

- 외부 `.js` + `th:attr="nonce=${cspNonce}"`.
- 요소별 초기화는 `htmx:load` 에서 **멱등** 처리(`data-initialized` 가드).
- 리스너 누적 주의 — document 레벨 리스너는 모듈 스코프에서 1회만 등록한다.
- 네이티브 요소 우선: 아코디언 `<details>/<summary>`, 모달 `<dialog>`.
- 뒤로가기 민감 화면은 `hx-history="false"`.

### 9-3. 정적 자원

- **self-host 만**(CDN 금지). 폰트·차트 라이브러리 등 모두 `static/` 아래.
- **정적 경로 permitAll 을 빠뜨리지 않는다** — 001에서 `/fonts/**` 누락으로 익명 요청 시 302 로그인 리다이렉트가 나
  `@font-face` 가 실패, **여태 시스템 폰트로 렌더**되던 것을 뒤늦게 발견했다.
  현재 필요한 경로: `/css/**`, `/js/**`, `/fonts/**`, `/img/**`, `/tmpl/**`.
- `local` 프로파일은 정적 자원 `no-store`(F5만으로 CSS 반영), `prod` 는 1년 immutable + fingerprint.

### 9-4. 레이아웃

- `fragments/layout-admin.html`(관리자) / `fragments/layout-front.html`(사용자).
- 공통 조각: breadcrumb, 페이지네이션, flash-alert, 파일 picker, 사이트 푸터.
- 멀티사이트: 사이트별 **시각 언어는 다를 수 있으나**(KRDS / IBM Carbon 등),

### 9-5. 위지윅 에디터

**공통 모듈을 경유**한다. 엔진은 **tiptap(기본)** 과 **Namo CrossEditor 4** 2종.

```html
<textarea name="body" data-editor></textarea>            <!-- 전역 기본 엔진 -->
<textarea name="body" data-editor="tiptap"></textarea>   <!-- 화면 단위 지정(전역보다 우선) -->

```

| 항목 | 규약 |
|---|---|
| 전역 기본 엔진 | `application.yml` 설정값. 미지원 값이면 기본 엔진으로 폴백(설정 오타로 화면 전체가 죽지 않게) |
| 값 전달 | **원본 `<textarea>` 로 동기화** — 컨트롤러·DTO 변경 불필요 |
| 동기화 시점 | 내용 변경 시 + 폼 submit 캡처 단계 + htmx 요청 직전 |
| 옵션 | `data-editor-height`(px), `data-editor-toolbar`(`full`/`basic`/`none`) |
| 엔진 추가 | 어댑터 계약 `isAvailable()` / `load()` / `mount()` 구현 후 등록 |
| 툴바 | DOM API 로 생성(인라인 핸들러 금지). 커맨드가 없으면 버튼을 만들지 않는다 |
| 로딩 | 벤더 스크립트는 **에디터가 있는 화면에서만 지연 로드**. 로드 전까지 원본 textarea 가 보여 입력이 막히지 않는다 |
| tiptap | **ESM 전용** — 브라우저 직접 로드 불가. 번들 후 self-host |
| Namo | **상용** — 배포 파일이 저장소에 없다. 미반입 시 **평문 textarea 폴백**(폼 제출 정상) |
| 보안 | **에디터 산출 HTML 은 신뢰 입력이 아니다** — 저장 경로에서 **OWASP Sanitizer 필수** |

### 10-1. 인증 · 인가

- **다중 SecurityFilterChain**

| 체인 | Order | 특징 |

| admin | 10 | IP 화이트리스트 + 2FA |

### 10-4. PII

- `@Encrypt`(AES-256-GCM, **`{AG}` 프리픽스**) + MyBatis `EncryptInterceptor` 로 투명 암복호화.
- `MaskUtils` 마스킹 + `log_privacy_access` 접근 기록(`@PrivacyAccess` + Aspect).
- 마스터키 미주입 시 **fail-fast**.
- 파기 이력은 `tb_pii_purge_log`.

#### 이름(`*_name`) 저장 정책 (2026-07-31 확정)

| 테이블·컬럼 | 저장 형태 | 이유 |
|---|---|---|
| `tb_admin.admin_name` | **평문** `varchar(150)` | 관리자 이름은 평문으로 관리한다 |
| `tb_admin_withdraw.admin_name` | **마스킹** `varchar(150)` | 탈퇴 관리자는 ID·입증정보가 부족하다. 이름을 남기되 마스킹해 식별 가능성을 낮춘다 |
| `tb_member_withdraw.member_name` | **마스킹** `varchar(150)` | 위와 동일 |
| `tb_member.member_name`, `tb_member_dormant.member_name` | **평문** `varchar(150)` (001 실측) | 이름 외 PII(`email`·`phone`·`birth_date`·`di`·주소)만 `@Encrypt` 대상이다 |
| `tb_employee.employee_name` | `@Encrypt` **`{AG}`** `varchar(512)` | 001 실측 그대로 유지 — 이름 컬럼 중 유일하게 암호화된다 |

- **탈퇴 테이블에는 `@Encrypt` 를 붙이지 않는다.** 마스킹된 값을 그대로 저장한다 —
  복호화 가능한 암호문으로 두면 "보관 최소화" 취지에 어긋난다.
- 마스킹은 `MaskUtils` 로 **저장 시점에 1회** 수행한다. 원본은 남기지 않는다(되돌릴 수 없다).
- `tb_admin.admin_name` 은 평문이므로 `@Encrypt` 대상에서 제외한다 —
  이 컬럼에 `@Encrypt` 가 남아 있으면 `{AG}` 접두 암호문이 150자를 넘겨 **저장 실패**한다.

### 10-5. 비밀값 관리

- **환경변수로만 주입.** yml 에 기본값을 박지 않는다 — `${VAR}` 만 사용(`${VAR:실제값}` 금지).
- **`.env` 는 커밋 금지**(`.gitignore`).
- **`.env.example` 은 키 이름 + `__CHANGE_ME__` 플레이스홀더만** 둔다.
  001에서 example 이 실제 `.env` 사본이라 운영 비밀값 21종이 커밋 직전까지 갔다.
  비밀이 아닌 값(경로·드라이버 클래스·localhost URL)만 예시값을 남긴다.
- 배포 시 비밀값은 `conf/pcms.env`(권한 600)로 분리 — `setenv` 스크립트에 넣지 않는다.
- **커밋 전 `git status` 로 `.env` 스테이징 여부를 확인한다.**

### 10-6. 휴면 해제 본인확인 — 실명인증 / 이메일 OTP **택1**

휴면(`tb_member_dormant`) → 일반(`tb_member`) 전환 시 본인확인을 거친다.
**두 수단 중 사용자가 하나를 선택**한다.

| 수단 | 근거 | 사용 자원 |
|---|---|---|
| **A. 실명인증** | NICE 본인인증 결과의 **DI 해시**(`di_hash`)가 휴면 스냅샷과 일치 | `primary/identity` — `NiceCheckService` |
| **B. 이메일 OTP** | 가입 시 등록된 이메일로 발송한 일회용 코드 검증 | **`tb_member_otp`**(신규) + `common/mail/MailService` |

> **001과의 차이**: 001의 휴면 해제는 NICE 실명인증이 아니라
> **로그인ID + 이름 + 이메일 + 비밀번호 3요소 일치**(`DormantRestoreForm`)였다.
> 003은 위 두 수단 중 택1로 대체한다. 이식할 때 001 코드를 그대로 가져오면 안 된다.

#### 공통 규칙

- 어느 경로로 성공하든 이후 처리는 동일 — `tb_member_dormant` → `tb_member` 역이관 + `restored_at` 기록.
- **계정 열거(enumeration) 차단** — 존재하지 않는 계정에도 **동일한 응답과 동일한 소요 시간**을 준다.
  "가입되지 않은 계정입니다" 류의 구분 가능한 메시지를 내지 않는다.
- 시도는 `log_security` 에, 개인정보 조회는 `log_privacy_access` 에 기록한다.
- 두 경로 모두 Bucket4j **레이트리밋** 대상.

#### 이메일 OTP 규칙

| 항목 | 값 | 근거 |
|---|---|---|
| 코드 형식 | 숫자 6자리 | 입력 편의 |
| 유효시간 | **5분** | 짧게 유지 |
| 시도 제한 | **5회** 초과 시 해당 OTP 폐기(재발급 필요) | 무차별 대입 차단 |

#### `tb_member_otp` (신규)

용도(`purpose`)를 두어 휴면 해제 외 다른 흐름(이메일 변경 확인 등)에도 재사용할 수 있게 한다.

```sql

  `expire_at`     datetime    NOT NULL COMMENT '만료 일시',
  `attempt_count` int(11)     NOT NULL DEFAULT 0 COMMENT '검증 시도 횟수',
  `verified_at`   datetime    DEFAULT NULL COMMENT '검증 성공 일시',
  `used_yn`       char(1)     NOT NULL DEFAULT 'N' COMMENT '사용 여부 (1회용)' CHECK (`used_yn` in ('Y','N')),
  `request_ip`    varchar(50) DEFAULT NULL COMMENT '요청 IP',
  `delete_yn`     char(1)     NOT NULL DEFAULT 'N' COMMENT '삭제 여부' CHECK (`delete_yn` in ('Y','N')),
  created_by varchar(40) DEFAULT NULL COMMENT '생성자 ID',
  created_ip varchar(50) DEFAULT NULL COMMENT '생성자 IP',
  created_at timestamp   DEFAULT current_timestamp() COMMENT '생성 일시',
  updated_by varchar(40) DEFAULT NULL COMMENT '수정자 ID',
  updated_ip varchar(50) DEFAULT NULL COMMENT '수정자 IP',
  updated_at timestamp   DEFAULT current_timestamp() ON UPDATE current_timestamp() COMMENT '수정 일시',
  PRIMARY KEY (`otp_id`),
  KEY `ix_member_otp_lookup` (`purpose`,`email_hash`,`expire_at`),
  KEY `ix_member_otp_member` (`member_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_uca1400_ai_ci COMMENT='회원 이메일 OTP (일회용 인증코드)';
```

> 유효시간(5분)·자릿수(6)·시도 제한(5회)은 정책값이다. 바꾸려면 `application.yml` 로 외부화하고
> 이 표와 해당 키 주석을 함께 갱신한다.

## 14. 예외 · 오류 처리

- 도메인 예외는 **의미 있는 예외 타입**으로 던지고, 컨트롤러에서 사용자 메시지로 변환한다.
- **CUD 는 try-catch + `log.error`(식별자 포함) + flash 메시지**. 스택트레이스를 화면에 노출하지 않는다.
- 전역 예외는 `ErrorLoggingExceptionResolver` 가 `log_error` 에 적재.
- **htmx 요청의 인증/인가 실패**는 조각 swap 을 막아야 한다:
  - 미인증 → `HX-Redirect` + 401 (전체 페이지 로그인 전환)
  - 인가 거부 → `HX-Reswap: none`
  - 302 를 XHR 이 투명 추종해 **로그인 페이지가 조각에 swap 되는 사고**가 001에서 실제로 있었다.
- 오류 페이지는 프로파일과 무관하게 내부 정보를 노출하지 않는다.

## 16. 작업 원칙

001·002에서 범위가 불어나 되돌린 경험을 반영한 규칙이다.

1. **요청 범위에서 멈춘다.** 곁다리 발견은 [PLAN.md](PLAN.md) §7 에 **기록만** 하고 고치지 않는다.
2. **플랜에 없는 작업은 하지 않는다.** 필요하면 PLAN 에 항목을 먼저 추가하고 승인받는다.
3. **한 커밋 = 한 주제.** 리팩터링·정리·기능을 섞지 않는다.
4. **새 의존성·빌드 단계 추가는 사전 확인.**
5. **질문은 최소로** — 합리적 기본값이 있으면 진행하고 가정을 명시한다. 되돌리기 어렵거나 위험한 것만 묻는다.
6. **파괴적 변경 전 되돌릴 지점 확보**(커밋).
7. **문서와 실측이 다르면 실측이 맞다.** 문서를 고친다.
8. **001 이식 시 `Egov` 접두 클래스명은 리네이밍한다.** 호환성 규칙 7 —
   실행환경(`org.egovframe.rte`) 클래스를 상속한 클래스는 이름이 `Egov` 로 시작할 수 없다
   (공통컴포넌트·개발환경 템플릿을 그대로 재사용하는 경우만 예외).
   001 의 `EgovXxx` 를 복사해 오면 **호환성 위반**이 된다.

## 17. 배포

- war 를 **외부 Tomcat 10.1.x(Java 21)** 에 배포. 배포 자산은 `deploy/tomcat/`.
- `setenv.sh`/`setenv.bat` 가 처리하는 것:
  - **NICE 본인인증 JPMS 플래그** — `--add-exports/--add-opens java.base/com.sun.crypto.provider=ALL-UNNAMED`
    (누락 시 본인인증에서만 500. surefire·`spring-boot:run`·운영 setenv **모두**에 필요)
  - `spring.profiles.active=prod`
  - `conf/pcms.env` 환경변수 로드(값의 `&`·`()` 특수문자 안전 처리)
  - UTF-8 · `Asia/Seoul` · headless · 힙(`JVM_MEM_OPTS` override)
- war 는 **표준 war 로 배포**(spring-boot repackage 안 함 — BOOT-INF 중첩 구조는 외부 Tomcat ClassLoader 와 비호환).
- 프로파일

| 프로파일 | 용도 | 특징 |
|---|---|---|
| `local` | 개발(기본) | 쿠키 secure=false, Thymeleaf 캐시 off, 정적 리소스 **no-store** |
| `dev` | 통합 | 프록시/터널 뒤 |
| `prod` | 운영 | Swagger 비활성, tracing 샘플링 축소, 정적 리소스 1년 immutable + fingerprint |

- 비밀값 미주입 시 **fail-fast 부팅 실패는 의도된 동작**이다.
